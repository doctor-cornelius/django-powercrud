## Selection repairs

The patch is confined to selection logic in [runtests](../../../../runtests), its regression tests, and documentation:

1. **Directory ownership and settings isolation.** Normalize the filesystem portion of each argument with GNU `realpath`, separately from its `::` node selector, and forward that normalized path to pytest so exclusions use the same path. This handles leading `./`, trailing slashes, parent segments, and directory aliases without rewriting parameter IDs. Reject directories containing both suites, including `.` and `src`, before preflight or pytest, and explain `--suite all --pytest`. Explicit suite selection cannot bypass the rejection. Focused `src/tests` directory selections exclude the minimal-settings module and print its separate command. One shared argument array applies the exclusion to focused execution and collection, including the existing plain and browser routes. The full consumer route retains its separate minimal-settings process.
2. **Compatible minimal selections.** Track ordinary consumers separately from the minimal module. Several nodes from that module can run together under `tests.settings_minimal`; explicit mixtures with ordinary files or directories still fail before commands execute. Focused ordinary consumers retain custom/Bootstrap settings. Coordinator paths continue to force coordinator settings.

Eight new parameterized/non-parameterized test functions provide **27 collected selection cases** in [test_runtests.py](../../../../src/coordinator_tests/test_runtests.py). They cover all three entry modes (plain paths, `--pytest`, collection), ancestor rejection, explicit-suite rejection, directory exclusion, equivalent spellings, multiple minimal nodes, mixed settings, and parameter IDs containing path-like text. The existing command stubs keep these routing checks independent of real browser/build actions. No existing behavioral assertion or coverage-related test was edited.
