## Current behavior and dependency flow

PowerCRUD's bulk view decides whether an operation queues from the view's `bulk_async` settings, the q2 import/app check, and the configured record threshold. When queued, it resolves a configured manager, generates a task UUID, and calls `launch_async_task` with a PowerCRUD worker path, conflict IDs, manager class/config, and bulk persistence arguments. The relevant code is in [async_mixin.py](../../../../src/powercrud/mixins/async_mixin.py#L23) and [bulk_view_mixin.py](../../../../src/powercrud/mixins/bulk_mixin/view_mixin.py#L400).

`AsyncManager` imports q2 `Task`, `async_task`, `fetch`, and `delete_cached` at module import. Construction resolves a PowerCRUD cache alias and settings, rejects missing/local-memory cache backends by a class-name check, and reads `Q_CLUSTER`. Launch reserves object keys, initializes progress, calls q2 with the hard-coded `powercrud.async_hooks.task_completion_hook`, then adds the task to a shared active-task set and emits `create`. See [async_manager.py](../../../../src/powercrud/async_manager.py#L20), [configuration](../../../../src/powercrud/async_manager.py#L101), and [launch](../../../../src/powercrud/async_manager.py#L324).

The q2 hook parses task kwargs and reconstructs a manager from a dotted path/config, falling back to base `AsyncManager` on resolution errors. The bulk workers independently reconstruct the same manager path/config, call business logic, emit progress, and return a boolean. The hook then removes active/lock/progress state and emits terminal lifecycle events from q2's task success flag/result. See [async_hooks.py](../../../../src/powercrud/async_hooks.py#L20), [completion handling](../../../../src/powercrud/async_manager.py#L1169), and [tasks.py](../../../../src/powercrud/tasks.py#L19).

Progress polling reads cache-only progress/status and returns a JSON response. `ModelTrackingAsyncManager` persists lifecycle events through a configured Django model; the sample subclass and CRUD dashboard are consumer integration. Context uses `ContextVar`, but descendant registration constructs base `AsyncManager` directly. Cleanup can run from a PowerCRUD management command or q2 schedule and queries q2 `Task` rows before removing artifacts. See [polling](../../../../src/powercrud/async_manager.py#L1024), [tracking](../../../../src/powercrud/async_dashboard.py#L39), [context](../../../../src/powercrud/async_context.py#L37), [schedule](../../../../src/powercrud/schedules.py#L1), and [command](../../../../src/powercrud/management/commands/pcrud_cleanup_async.py#L1).

The dependency direction is therefore only partly separated: coordinator state/lifecycle, q2 transport/result access, PowerCRUD settings, reusable endpoint, and model tracking live in PowerCRUD modules. CRUD workers, view choices, presentation, and sample dashboard are PowerCRUD integration. The current q2 import boundary is not lazy: `async_manager.py` raises `ImproperlyConfigured` if q2 imports fail, and `AsyncMixin` imports that manager at module load. `async_hooks.py` also imports `django_q.models.Task` at module load.

### Fixture, settings, and discovery evidence

- `src/tests/async_tests/test_sys_functions.py` imports `django_q`, `Cluster`, manager/hook/mixin modules, test workers, sample models, and `SampleAsyncManager` at module scope. `AsyncManagerTestMixin.setUp()` clears the selected cache entirely. `BaseAsyncQ2Instance` starts a cluster thread. `Q_CLUSTER['sync']=True` is only a default: manager launches explicitly pass `sync=False`; the health probe omits that option and can execute inline. - `pytest.ini` sets `pythonpath=src`, `DJANGO_SETTINGS_MODULE=tests.settings`, and `--cov=powercrud`. Current `runtests` accepts test paths and preserves an explicitly supplied settings module for focused invocations, but has no suite/config/coverage selector. Default no-path invocations reset settings to `tests.settings`. CI's unrestricted pytest discovery could collect a new tree, but would apply the same settings; separate suite invocations are needed for isolation, not merely discovery.
- Suite independence requires explicit pytest config or equivalent invocation that selects suite settings, URLs, fixtures, cache resources, and coverage targets. The future package tree needs minimal models and importable top-level workers. Real absent-dependency and import-before-settings coverage requires process/environment isolation.
